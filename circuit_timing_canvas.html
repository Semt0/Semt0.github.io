🔧 电路时序基础概念详解

1. 为什么需要时序？

在数字电路中，数据从触发器（DFF）输出，经过组合逻辑，到达下一个触发器输入。由于电子信号传播需要时间，我们必须考虑三个关键因素：

⚡ 门延迟

逻辑门（AND、OR、NOT等）处理输入并产生输出所需的时间。通常以皮秒（ps）或纳秒（ns）为单位。

📡 线延迟

信号在物理连线上传播所需的时间，取决于连线长度、层数和制造工艺。

🔒 时钟偏斜

同一时钟信号到达不同触发器的时间差异，由时钟树不平衡或工艺变化引起。

2. 时序路径与时钟域

CLK：时钟信号
发射沿：源触发器采样时刻
Tco：时钟到输出延迟
Tcomb：组合逻辑延迟
捕获沿：目标触发器采样时刻
Ts：建立时间窗口
Tclk：时钟周期

波形图符号说明：

  • T0/T1/T2：连续时钟沿的标记点
  • 黄色高亮区：Tco 延迟，从时钟沿到数据从触发器输出的时间
  • 绿色高亮区：建立时间窗口 Ts，数据必须在此时刻前稳定
  • 紫色信号：组合逻辑处理后的数据，存在延迟和可能的毛刺
  • 红色信号：源触发器输出，与发射沿对齐

🔑 关键概念：时序路径三要素

  • 发射沿 (Launch Edge)：源触发器采样的时钟沿，数据从此刻开始传播。对应时间 Tlaunch
  • 锁存沿/捕获沿 (Latch/Capture Edge)：目标触发器采样的时钟沿，数据必须在此之前稳定。对应时间 Tcapture
  • 数据到达时间 (Data Arrival Time)：从发射沿到数据到达目标触发器输入的总时间 = Tco + Tcomb
  • 数据要求时间 (Data Required Time)：锁存沿前必须满足建立时间 = Tcapture - Tsetup

3. 时序约束三要素详解

📏 建立时间 (Setup Time)

在时钟上升沿到来之前，数据必须保持稳定的最短时间。

Tsetup = 时钟沿到达时刻 - 数据稳定时刻 (必须 ≥ 0)

Tsetup 是触发器的固有属性，由触发器内部电路决定。如果建立时间不足，触发器采样时数据还在变化，可能导致亚稳态。

🔒 保持时间 (Hold Time)

在时钟上升沿到来之后，数据必须继续保持稳定的最短时间。

Thold = 数据变化时刻 - 时钟沿到达时刻 (必须 ≥ 0)

Thold 也是触发器的固有属性。如果保持时间不足，新的数据"太快"到达，可能被同一时钟沿误采样为下一拍的数据。

⚡ 传播延迟 (Propagation Delay)

从输入变化到输出响应的最大时间延迟，包括门延迟和线延迟。

tpd = Σ(门延迟) + Σ(线延迟)

tpd 决定信号通过组合逻辑的时间。关键路径（Critical Path）是电路中最长的组合逻辑路径，直接决定了电路的fmax。

4. 建立时间与保持时间约束公式

📐 建立时间约束（Setup Constraint）

确保数据在捕获时钟沿之前稳定到达：

Tlaunch + Tco + Tcomb + Tsetup ≤ Tcapture + Tclk - Tskew

简化为： Tco + Tcomb + Tsetup ≤ Tclk - Tskew

符号说明：

  • Tlaunch / Tcapture：发射沿/捕获沿的绝对时间（通常设 Tlaunch = 0）
  • Tco：时钟到输出延迟（Clock-to-Q）
  • Tcomb：组合逻辑延迟（Combinational Delay）
  • Tsetup：建立时间（Setup Time）
  • Tclk：时钟周期（Clock Period）
  • Tskew：时钟偏斜（Skew），正偏斜表示捕获时钟晚到，有利于建立时间

💡 若违反：增加时钟周期（降低频率）、优化组合逻辑、使用时钟偏斜管理

🔐 保持时间约束（Hold Constraint）

确保数据在捕获时钟沿之后不会太快变化：

Tlaunch + Tco + tcd ≥ Tcapture + Thold + Tskew

简化为： Tco + tcd ≥ Thold + Tskew

符号说明：

  • tcd：污染延迟（Contamination Delay），即组合逻辑的最小延迟（最快路径）
  • Thold：保持时间（Hold Time）
  • Tskew：时钟偏斜，正偏斜不利于保持时间
  • 注意：保持时间分析使用最小延迟路径，与建立时间（用最大延迟）相反

💡 若违反：在路径中插入缓冲器（增加延迟）、修复时钟树、检查工艺角（FF角更容易违例）

时序违例可视化

s 数据变化太快! 数据到达(100ns) < 建立要求(120ns-Ts=100ns)，发生违例 保持时间违例 (Hold Violation) ↑ 发射沿 ↑ 捕获沿 Th 数据变化太早! 数据变化(60ns) < 保持要求(60ns+Th)，新数据太快到达
波形图符号说明：
  • ↑ 发射沿：源触发器的时钟采样沿，数据从此刻开始传播
  • ↑ 捕获沿：目标触发器的时钟采样沿，数据必须在此刻满足时序要求
  • Ts：建立时间窗口（绿色区域），数据必须在此窗口前稳定
  • Th：保持时间窗口（黄色区域），数据必须在此窗口内保持稳定
  • 建立违例：数据到达捕获沿时还在变化，建立时间不足
  • 保持违例：数据在捕获沿后太快变化，保持时间不足

5. 建立时间与保持时间的权衡

🔄 时钟周期 vs 频率

fmax = 1000 / (Tco + Tcomb_max + Tsetup + Tskew) (MHz)

Tsetup 限制最高频率 fmax。Thold 与时钟频率无关，但与最小路径延迟有关。

📊 时序裕量（Slack）

Setup Slack = 数据要求时间 - 数据到达时间
Hold Slack = 数据稳定时间 - 保持时间要求

正的 Slack 表示时序满足；负的 Slack 表示时序违例。

特性 建立时间 Tsetup 保持时间 Thold
相对时钟沿 时钟沿之前（Pre） 时钟沿之后（Post）
延迟路径 使用最大延迟 Tcomb_max（最坏情况） 使用最小延迟 tcd（最快路径）
与时钟频率关系 直接相关（限制 fmax） 无关（任何频率都可能违例）
PVT角影响 慢工艺(SS)、高温、低电压时更差 快工艺(FF)、低温、高电压时更差
常见解决方式 降低频率、优化组合逻辑、pipeline 插入缓冲器、修复时钟树
裕量计算 Slack = 要求时间 - 到达时间 Slack = 稳定时间 - 要求时间

6. 时序分析工具与方法

📐 静态时序分析 (STA)

不运行仿真，通过数学分析检查所有时序路径。是工业界标准做法。

  • 计算每个路径的最坏情况延迟
  • 检查建立/保持时间约束
  • 报告时序裕量和违例路径

🎮 动态仿真

通过实际仿真波形观察时序行为，用于验证 STA 结果和调试。

  • 需要完整的测试向量
  • 无法覆盖所有场景
  • 适合调试特定问题

🔧 PVT 角分析

在不同工艺(Process)、电压(Voltage)、温度(Temperature)条件下分析。

  • SS: 慢工艺、低电压、高温（最慢）
  • FF: 快工艺、高电压、低温（最快）
  • TT: 典型情况

7. 实际案例与常见错误

❌ 常见错误 #1：跨时钟域 (CDC) 处理不当

当数据从一个时钟域传到另一个异步时钟域时，必须使用同步器（通常两级触发器）或握手协议。

错误：直接连接不同频率的时钟域 → 导致亚稳态和数据丢失

⚠️ 常见错误 #2：复位信号时序

异步复位信号的释放（release）需要满足恢复时间（Recovery）和撤销时间（Removal）约束。

Recovery Time: 复位释放到时钟沿的时间
Removal Time: 时钟沿到复位释放的时间

✅ 最佳实践

  • 始终运行完整的 STA 流程，检查所有 PVT 角
  • 确保建立时间裕量 > 10% 时钟周期
  • 保持时间违例更难修复，应在设计早期关注
  • 使用时钟门控（Clock Gating）降低功耗时，注意门控信号的时序
  • 跨时钟域信号必须经过同步器处理

9. 核心要点总结

🎯 建立时间 (Setup)

时钟沿前数据必须稳定。限制最高频率 fmax。

Tco + Tcomb + Tsetup ≤ Tclk - Tskew

🎯 保持时间 (Hold)

时钟沿后数据必须保持。与时钟频率无关。

Tco + tcd ≥ Thold + Tskew

🎯 传播延迟

信号通过逻辑门和连线的总延迟。

tpd = Σ(门延迟) + Σ(线延迟)

🎯 时序裕量 (Slack)

满足时序约束的剩余时间。必须 > 0

Slack = 要求时间 - 到达时间
